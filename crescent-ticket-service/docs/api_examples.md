# API examples (curl)

These commands demonstrate the complete Version 1 business flow against a
running service. They capture the IDs generated by each response and reuse
them in later requests; nothing is hard-coded.

**Prerequisites**: PGlite and the API are running (README, *Running the
service*). Run everything in **one bash shell**, starting in the project
directory `crescent-ticket-service/`. Only `curl` and `python3` are used.

## 0. Setup

```bash
BASE_URL="http://127.0.0.1:8000"
API_KEY="$(grep '^API_KEY=' .env | cut -d= -f2-)"
WORK="$(mktemp -d)"                 # response bodies are saved here
RUN_ID="$(date +%s)$(printf '%02d' $((RANDOM % 100)))"   # unique per run (12 digits)
PHONE="+999${RUN_ID}"               # +999 is an unassigned country code (fictional number)

# field FILE KEY -> prints one field of a saved JSON response
field() { python3 -c 'import json, sys; print(json.load(open(sys.argv[1]))[sys.argv[2]])' "$1" "$2"; }

curl -sS "$BASE_URL/health/ready"; echo
```

Expected: `{"status":"ready","checks":{"database":"ok","migrations":"ok","company":"ok"}}`

Every request below prints the response body followed by `HTTP <code>`.

## 1. Create a customer

```bash
curl -sS -X POST "$BASE_URL/api/v1/customers" \
  -H "X-API-Key: $API_KEY" -H "Content-Type: application/json" \
  -d "{\"name\": \"Demo Customer\", \"phone_number\": \"$PHONE\"}" \
  -o "$WORK/customer.json" -w "HTTP %{http_code}\n"
cat "$WORK/customer.json"; echo
CUSTOMER_ID="$(field "$WORK/customer.json" id)"
```

Expected: `HTTP 201`; body contains `"id"`, `"name": "Demo Customer"`,
`"phone_number": "+999..."` (normalized). Sending the same phone number again
returns `HTTP 409` with `"code": "DUPLICATE_CUSTOMER"`.

## 2. Create a support agent

```bash
curl -sS -X POST "$BASE_URL/api/v1/agents" \
  -H "X-API-Key: $API_KEY" -H "Content-Type: application/json" \
  -d "{\"name\": \"Demo Agent\", \"email\": \"demo.agent.${RUN_ID}@example.com\"}" \
  -o "$WORK/agent.json" -w "HTTP %{http_code}\n"
cat "$WORK/agent.json"; echo
AGENT_ID="$(field "$WORK/agent.json" id)"
```

Expected: `HTTP 201`; `"is_active": true`.

## 3. Create a ticket

```bash
curl -sS -X POST "$BASE_URL/api/v1/tickets" \
  -H "X-API-Key: $API_KEY" -H "Content-Type: application/json" \
  -d "{\"customer_id\": \"$CUSTOMER_ID\", \"subject\": \"Car service delayed\", \"description\": \"The car was promised for Friday.\", \"priority\": \"HIGH\"}" \
  -o "$WORK/ticket.json" -w "HTTP %{http_code}\n"
cat "$WORK/ticket.json"; echo
TICKET_ID="$(field "$WORK/ticket.json" id)"
```

Expected: `HTTP 201`; `"status": "OPEN"`, `"priority": "HIGH"`, `"assigned_agent_id": null`, `"resolved_at": null`.

## 4. Verify the ticket is OPEN

```bash
curl -sS "$BASE_URL/api/v1/tickets/$TICKET_ID" -H "X-API-Key: $API_KEY" \
  -o "$WORK/ticket_open.json" -w "HTTP %{http_code}\n"
echo "status: $(field "$WORK/ticket_open.json" status)"
```

Expected: `HTTP 200` and `status: OPEN`.

## 5. Assign the agent

```bash
curl -sS -X PATCH "$BASE_URL/api/v1/tickets/$TICKET_ID/assign" \
  -H "X-API-Key: $API_KEY" -H "Content-Type: application/json" \
  -d "{\"agent_id\": \"$AGENT_ID\"}" \
  -o "$WORK/assigned.json" -w "HTTP %{http_code}\n"
cat "$WORK/assigned.json"; echo
```

Expected: `HTTP 200`; `"assigned_agent_id"` equals `$AGENT_ID`. An inactive
agent returns `HTTP 409` `AGENT_INACTIVE`; an unknown agent `HTTP 404` `AGENT_NOT_FOUND`.

## 6. Verify IN_PROGRESS

```bash
curl -sS "$BASE_URL/api/v1/tickets/$TICKET_ID" -H "X-API-Key: $API_KEY" \
  -o "$WORK/ticket_in_progress.json" -w "HTTP %{http_code}\n"
echo "status: $(field "$WORK/ticket_in_progress.json" status)"
```

Expected: `HTTP 200` and `status: IN_PROGRESS`.

## 7. Add a customer message

```bash
curl -sS -X POST "$BASE_URL/api/v1/tickets/$TICKET_ID/messages" \
  -H "X-API-Key: $API_KEY" -H "Content-Type: application/json" \
  -d '{"sender_type": "CUSTOMER", "message_text": "Any update on my car?"}' \
  -o "$WORK/message.json" -w "HTTP %{http_code}\n"
cat "$WORK/message.json"; echo

curl -sS "$BASE_URL/api/v1/tickets/$TICKET_ID/messages" -H "X-API-Key: $API_KEY" -w "\nHTTP %{http_code}\n"
```

Expected: `HTTP 201` with `"sender_type": "CUSTOMER"`, `"source": "API"`; the
list returns `HTTP 200` with the message in `"items"` (chronological order).

## 8. Resolve the ticket

```bash
curl -sS -X PATCH "$BASE_URL/api/v1/tickets/$TICKET_ID/status" \
  -H "X-API-Key: $API_KEY" -H "Content-Type: application/json" \
  -d '{"status": "RESOLVED"}' \
  -o "$WORK/resolved.json" -w "HTTP %{http_code}\n"
cat "$WORK/resolved.json"; echo
```

Expected: `HTTP 200`; `"status": "RESOLVED"` and a `"resolved_at"` timestamp.

## 9. Verify RESOLVED

```bash
curl -sS "$BASE_URL/api/v1/tickets/$TICKET_ID" -H "X-API-Key: $API_KEY" \
  -o "$WORK/ticket_resolved.json" -w "HTTP %{http_code}\n"
echo "status: $(field "$WORK/ticket_resolved.json" status), resolved_at: $(field "$WORK/ticket_resolved.json" resolved_at)"

curl -sS "$BASE_URL/api/v1/tickets/$TICKET_ID/events" -H "X-API-Key: $API_KEY" -w "\nHTTP %{http_code}\n"
```

Expected: `HTTP 200`, `status: RESOLVED`; the events list shows
`TICKET_CREATED`, `AGENT_ASSIGNED`, `STATUS_CHANGED` (OPEN to IN_PROGRESS),
`STATUS_CHANGED` (IN_PROGRESS to RESOLVED), `TICKET_RESOLVED`.

Trying to reopen it is rejected:

```bash
curl -sS -X PATCH "$BASE_URL/api/v1/tickets/$TICKET_ID/status" \
  -H "X-API-Key: $API_KEY" -H "Content-Type: application/json" \
  -d '{"status": "OPEN"}' -w "\nHTTP %{http_code}\n"
```

Expected: `HTTP 409`, `"code": "INVALID_STATUS_TRANSITION"`.

## 10. Submit a new simulated customer message

```bash
curl -sS -X POST "$BASE_URL/api/v1/intake/messages" \
  -H "X-API-Key: $API_KEY" -H "Content-Type: application/json" \
  -d "{\"customer_name\": \"Demo Customer\", \"phone_number\": \"$PHONE\", \"message_text\": \"My car service is delayed again\", \"external_message_id\": \"demo-msg-${RUN_ID}-001\"}" \
  -o "$WORK/intake.json" -w "HTTP %{http_code}\n"
cat "$WORK/intake.json"; echo
NEW_TICKET_ID="$(field "$WORK/intake.json" ticket_id)"
```

Expected: `HTTP 201`; `"new_ticket_created": true`, `"customer_created": false`,
`"duplicate": false`, `"ticket_status": "OPEN"`, and `"customer_id"` equal to `$CUSTOMER_ID`.

## 11. Verify a NEW ticket was created

```bash
echo "old ticket: $TICKET_ID"
echo "new ticket: $NEW_TICKET_ID"
curl -sS "$BASE_URL/api/v1/customers/$CUSTOMER_ID/tickets" -H "X-API-Key: $API_KEY" \
  -o "$WORK/history.json" -w "HTTP %{http_code}\n"
python3 -c 'import json, sys; [print(t["id"], t["status"]) for t in json.load(open(sys.argv[1]))["items"]]' "$WORK/history.json"
```

Expected: the two IDs differ; `HTTP 200`; the history lists two tickets, newest
first: `<new ticket> OPEN` then `<old ticket> RESOLVED`.

## 12. Verify the old ticket remains RESOLVED

```bash
curl -sS "$BASE_URL/api/v1/tickets/$TICKET_ID" -H "X-API-Key: $API_KEY" \
  -o "$WORK/old_ticket.json" -w "HTTP %{http_code}\n"
echo "old ticket status: $(field "$WORK/old_ticket.json" status)"
```

Expected: `HTTP 200` and `old ticket status: RESOLVED`.

## Duplicate message: same `external_message_id` twice

```bash
DUP_BODY="{\"customer_name\": \"Demo Customer\", \"phone_number\": \"$PHONE\", \"message_text\": \"Is anyone there?\", \"external_message_id\": \"demo-msg-${RUN_ID}-dup\"}"

curl -sS -X POST "$BASE_URL/api/v1/intake/messages" \
  -H "X-API-Key: $API_KEY" -H "Content-Type: application/json" \
  -d "$DUP_BODY" -o "$WORK/dup1.json" -w "HTTP %{http_code}\n"
cat "$WORK/dup1.json"; echo

curl -sS -X POST "$BASE_URL/api/v1/intake/messages" \
  -H "X-API-Key: $API_KEY" -H "Content-Type: application/json" \
  -d "$DUP_BODY" -o "$WORK/dup2.json" -w "HTTP %{http_code}\n"
cat "$WORK/dup2.json"; echo

curl -sS "$BASE_URL/api/v1/tickets/$(field "$WORK/dup1.json" ticket_id)/messages" -H "X-API-Key: $API_KEY" \
  -o "$WORK/dup_messages.json" -w "HTTP %{http_code}\n"
python3 -c 'import json, sys; items = json.load(open(sys.argv[1]))["items"]; print("stored copies:", sum(m["external_message_id"] == sys.argv[2] for m in items))' \
  "$WORK/dup_messages.json" "demo-msg-${RUN_ID}-dup"
```

Expected:

- first request `HTTP 201`, `"duplicate": false`;
- second request `HTTP 200`, `"duplicate": true`, with the **same** `ticket_id`
  and `message_id` as the first;
- `stored copies: 1`.

Reusing the same `external_message_id` with a different text or phone number
returns `HTTP 409` `EXTERNAL_MESSAGE_ID_CONFLICT`.

## Error examples

```bash
# Missing API key
curl -sS "$BASE_URL/api/v1/tickets" -w "\nHTTP %{http_code}\n"
# Unknown ticket
curl -sS "$BASE_URL/api/v1/tickets/00000000-0000-4000-8000-000000000000" -H "X-API-Key: $API_KEY" -w "\nHTTP %{http_code}\n"
# Missing required field
curl -sS -X POST "$BASE_URL/api/v1/customers" -H "X-API-Key: $API_KEY" -H "Content-Type: application/json" \
  -d '{"name": "No Phone"}' -w "\nHTTP %{http_code}\n"
# Invalid status value
curl -sS -X PATCH "$BASE_URL/api/v1/tickets/$NEW_TICKET_ID/status" -H "X-API-Key: $API_KEY" \
  -H "Content-Type: application/json" -d '{"status": "CLOSED"}' -w "\nHTTP %{http_code}\n"
```

Expected: `HTTP 401` `UNAUTHORIZED`; `HTTP 404` `TICKET_NOT_FOUND`;
`HTTP 422` `VALIDATION_ERROR` (details name `["body", "phone_number"]`);
`HTTP 422` `VALIDATION_ERROR`.

## Clean up

rm -rf "$WORK"
